# AI LifeLab · 人生实验室

从相似经历出发，把一个人生问题变成可验证的小行动。

人生实验室是面向知乎 × 黑客松场景开发的多 Agent 应用。项目将**经历检索、人生路径规划、情感陪伴**串成一条探索流程：先从知乎和站内授权案例中寻找参考，再选择适合自己的方向、完成阶段行动，最后把真实经历整理成可审阅、可选择分享的新案例。

前端以太空探索为主题：空间站是思考问题的起点，航线代表探索方向，星球代表成长阶段，星球附近的物件对应具体任务，奶龙宇航员是随时可以交流的随航伙伴。

> 当前实现为可在本地运行的全栈原型。模型默认统一使用 DeepSeek Flash，工作流由 LangGraph 编排，业务数据与检查点使用 SQLite 持久化。

| 模块 | 已实现能力 |

三个核心 Agent 通过持久化的背景、证据索引、计划版本和任务状态协作。经历复盘是独立的整理流程，只有经过用户授权的案例才进入共享检索。

## 三个 Agent 如何协作

### 1. 经历检索 Agent：先找到可参考的真实经历

**流程：问题理解 → 必要澄清 → 查询规划 → 检索 → 去重与结构化提取 → 证据核验与评分 → 缺口分析 → 补查或结束。**

- 从用户原话中提取专业、学历与阶段、目标、计划、起点能力、约束、已有行动及结果；不把用户没有提供的信息补成事实。
- 缺少影响检索方向的关键信息时，通过 LangGraph `interrupt` 暂停，集中向用户澄清；可以回答“暂不确定”。
- 首批并发执行 Q01、Q02，默认分别获取 **10、6 条**结果。Q01 尽量贴近原始情况，Q02 在保留核心背景的前提下补充表达。
- Q03、Q04 根据证据缺口按需生成，默认各取 **5 条**。只有已有证据表明同专业案例不足时才允许有说明的专业拓展，不擅自改变学历。
- 每次任务最多 **4 次知乎搜索请求**，失败和重试也计数；这是请求次数上限，不代表必须固定跑满四轮。
- 关键证据充分时提前结束；请求数、Token、活跃时间达到上限，或继续检索没有价值时停止，并明确保留的缺口。
- 首批知乎检索时同步召回最多 **6 个站内授权案例候选**，共用后续核验与评分流程；内部召回不占知乎请求次数。

来源按内容 ID 或规范化 URL 去重，案例按来源与人物称呼合并。字段保留引用原文并做支持性核验；知乎案例的证据通常来自接口返回的摘要或片段，不把摘要包装为已经阅读全文。来源不足时明确说明，不为了填满结果编造案例。

#### 匹配分与评分字段覆盖率

| 评分维度 | 初始权重 |
| --- | ---: |
| 专业 | 25% |
| 学历与阶段 | 20% |
| 目标方向 | 25% |
| 计划与路径 | 15% |
| 起点能力与行动 | 10% |
| 现实约束 | 5% |

模型依据已核验字段给出 `0 / 0.25 / 0.5 / 0.75 / 1` 五档匹配等级及理由，**程序计算最终分数**。

- **匹配分：0–100 分**，为启用维度的归一化权重与匹配等级的加权和。
- 用户未提供的维度不参与比较，其余启用维度的权重重新归一到 100%。
- 案例缺少可核验字段时保留“未知”，该维度贡献零分。
- **评分字段覆盖率：0–100%**，为能够得到有效评估的维度权重之和。它衡量评分依据的完整程度，不等于相似度，也不代表成功概率。
- 排序先考虑“背景接近 / 路径可参考 / 补充参考”的层级，再比较匹配分与字段覆盖率；默认展示前 5 个案例，可展开其余结果。

用于决定是否继续检索的**证据覆盖**与评分字段覆盖率是两项指标。提前结束还要求模型判断证据充分、关键维度达到覆盖条件，且每个要求覆盖的维度有至少两个独立来源支持；用户已提供的专业、学历和目标还需要满足对应匹配门槛。

#### 如何理解报告中的数量

| 页面统计 | 含义 |
| --- | --- |
| 原始命中 | 多次查询累计返回的命中条目数 |
| 来源去重 | 按内容 ID / URL 合并后的来源数 |
| 完成分析 | 当前没有待分析片段的来源数 |
| 经历候选 | 提取流程产生的候选案例数 |
| 保留案例 | 通过筛选和证据处理后实际保留的案例数 |
| 实际引用来源 | 保留案例涉及的独立来源数 |

来源数和案例数不相等：同一来源可能讲述不同人物，多次查询也可能命中同一来源。达到预算但仍有待分析资料时，报告会显示待处理来源数量与结束原因。

### 2. 人生路径 Agent：把参考经历变成行动

**流程：复用检索背景与证据 → 必要澄清 → 生成候选航线 → 用户选择 → 规划阶段 → 细化当前任务 → 实践与反馈 → 按需调整。**

- 检索结束且已有背景后，可进入太空探索；路径 Agent 复用已保存的检索结果，不重新调用知乎搜索。
- 生成 **3–4 条候选航线**，展示目标、走法、适合条件、投入、难点和第一步行动，支持对比与自定义目标。
- 选择后规划 **4–6 个阶段**，先细化当前阶段的 **2–4 个任务**，后续阶段在抵达或用户主动展开时再细化。
- 建议分别标注为**案例证据、综合建议、待验证假设**。即使案例较少，也能提出待验证的方向，但不冒充有案例支持。
- 每个任务有行动说明、产出、完成标准、依赖、预计投入与帮助提示；完成、跳过、重新打开均受服务端状态与依赖检查。
- 支持暂停 / 继续、切换航线、根据新情况调整计划、审阅调整方案和查看历史版本。调整草案需要确认后才保存新版本。
- 可随时返回原检索页，再次进入时恢复当前航程。

### 3. 情感陪伴 Agent：让奶龙陪你走下去

奶龙是全局随航伙伴，可在检索首页、探索档案、检索结果和人生探索中打开。没有路径时也能日常聊天；进入航程后可切换“日常陪伴 / 聊聊这条航线”，从“记录 / 求助”入口可关联具体任务。

- 支持**自在聊聊、先听我说、一起想办法**三种交流偏好。
- 结合真实任务、前置依赖、当前进度、有限的近期对话与摘要提供支持，可以把困难拆成一个更小的行动。
- 明确、唯一关联且符合条件的完成反馈可以更新进度，并展示用户自述依据与撤销入口；模糊反馈、否定、假设和他人成果不能自动记作用户完成。
- 其他操作以卡片等待选择。涉及计划调整时交回路径 Agent，沿用草案审阅和版本保存流程。
- 个人记忆只保存经用户确认的偏好、能力和约束，支持修改与删除；日常会话与各航程会话分别保存。
- 伙伴不执行任意电脑命令，不把自己的建议写成用户已完成的行动，也不把情绪支持包装为专业诊断。

#### 通用 Web Search 工具

需要公共资料、最新信息或官方文件时，模型通过 tool calling 按需调用 `web_search`：

**理解搜索需求与条件 → 动态生成 Query → Tavily Search → 候选去重与适用性重排 → 按需 Extract 精读 → 缺口补搜 → 引用校验与回答。**

- 不写死学校、专业、学历、年份、关键词或域名；域名不确定时不猜测官网。
- 每次提问最多 **2 轮、4 条搜索请求、4 个 URL 精读**，每条查询最多 6 条结果，证据充分时提前停止。
- 综合主体、事项、受众、适用时间与版本等条件挑选原文，目标来源优先精读，而非按发现顺序直接截取最前面的链接。
- 展示查询、来源目录、正文读取状态、连续原文引用及实际检索时间；同一链接的引用合并展示。
- 来源使用本轮 `W01` 等编号；未读到正文时如实说明，不把“找到标题”当成“已核实条款”。
- 用户可关闭联网；未配置 Tavily 时，普通聊天仍可使用。
- PDF 由提取服务尝试读取，当前没有独立 OCR，扫描件、登录页和复杂附件可能无法精读。

详细说明：[随航伙伴](docs/companion-agent.md) · [Web Search](docs/web-search.md)。

### 4. 经历复盘：让真实行动成为新的参考

在太空探索中点击“经历复盘”，选择实际结果并填写反馈。整理流程结合原问题、澄清、路径版本、有效任务进度和随航对话，分批提取事实并生成**私人案例草稿**。

用户可以核对引用依据、编辑标题、摘要、13 个结构字段和复盘内容。**只有审阅并确认匿名分享后**，公开副本才进入 SQLite FTS5 索引，供后续用户与知乎资料一起检索。

计划、助手建议和预计工时不能当作实际行动或投入的证据。公开副本不包含原始聊天与私人整理依据。用户可以撤回分享；修改已分享内容后需要重新授权。已经生成的历史对话文字不会因撤回分享而自动重写。

详细说明：[探索经历案例](docs/experience-cases.md)。

## 太空主题与交互

### 空间站检索首页

三维观景舱配合玻璃拟态输入台、金属窗框与灯带，窗外有缓慢自转的地球、卫星和闪烁星光。两侧舱壁透明，地面保留实体质感；相机固定，避免结构梁随鼠标晃动。首页提供可自行填写的探索模板，不预填具体专业和人物背景。

### 星球、任务与行动之星

- 航线代表探索方向，**一颗星球代表一个阶段，附近的物件代表具体任务**。
- 星球使用程序化 Shader 呈现金属表面、发光能量纹路、全息网格、扫描光带、双层轨道与环绕粒子，提供六组科技配色。
- 上方导航切换阶段，左侧查看星球与奶龙，右侧处理任务；点击物件与任务详情联动。
- 完成任务后，奶龙召唤黄色星星，飞向并点亮对应物件，再回到奶龙身边环绕。
- 星星数量根据当前计划的服务端完成记录计算；跳过不奖励，重新打开任务会扣回，刷新和轮询不会重复播放奖励。

### 奶龙气泡与传送舱

检索需要补充信息时，气泡从奶龙附近升起，飘到屏幕中央，展示以下两段文字，再炸开为光圈和小气泡消散；点击气泡可提前结束并定位到填写区：

> 请补充一些信息,让探索更贴近你<br>
> 这些信息会帮助确定检索方向，暂不确定也可以直接写下来

当前阶段任务处理完成后，点击“**登舱，前往下一站**”，会播放奶龙登舱、舱门闭合、推进尾焰、星轨穿行和抵达的动画。切换航线时，在新计划保存成功后播放同样的传送效果。

动画跟随已保存的位置变化触发；阶段预览、取消选择、切换失败和页面刷新不会误播放。传送动画可跳过，不代替任务完成或服务端状态更新。

### 主题与兼容性

支持深色 / 浅色模式并记住选择，探索档案支持搜索、状态筛选及**每页 10 条**分页。聊天面板、气泡与传送画面均适配手机。

三维模块按需加载，可暂停动态场景，并适配减少动态效果偏好。三维场景在后台或离屏时停止持续刷新，WebGL 不可用或渲染失败时使用本地静态图。奶龙形象使用透明 PNG，配合 SVG、CSS 和 Web Animations API 完成互动。

空间站实现说明：[空间站检索首页](docs/station-home.md)。

## 技术栈

| 层级 | 技术与用途 |
| --- | --- |
| 模型 | DeepSeek Flash；`langchain-openai` 提供模型与工具调用适配 |
| 工作流 | LangGraph、`interrupt`、SQLite Checkpointer：节点编排、人工等待与恢复 |
| 后端 | Python 3.12、FastAPI、Uvicorn、Pydantic：接口、异步任务与结构化校验 |
| 外部资料 | 知乎搜索 API、Tavily Search / Extract、httpx |
| 存储 | SQLite：账号、检索、路径、对话、案例与事件；FTS5：站内授权案例全文检索 |
| 前端 | React 19、TypeScript、Vite 7、React Router、TanStack Query |
| 界面 | Tailwind CSS 4、Radix Slot / shadcn 风格组件、Lucide、CSS 玻璃与金属质感 |
| 三维与动效 | Three.js、React Three Fiber、GLSL Shader、Canvas、SVG、Web Animations API |
| 状态同步 | SSE 真实节点事件 + 查询刷新，支持事件回看与持久化恢复 |
| 账号凭证 | 加盐 PBKDF2 密码哈希、HttpOnly 会话 Cookie、Fernet 加密保存 API Key |

当前站内检索使用 FTS5，尚未引入向量数据库或独立的神经网络 Reranker。具体依赖版本以 [requirements.txt](requirements.txt) 和 [frontend/package-lock.json](frontend/package-lock.json) 为准。

## 快速启动

### 1. 准备环境

- Python **3.12**。
- Node.js **22.12+**，或 **20.x 中的 20.19+ 版本**，以及 npm。
- 可用的知乎 Access Secret；需要联网工具时再配置 Tavily API Key。
- DeepSeek API Key：普通用户登录后填写自己的 Key；管理员可使用服务端配置。

以下命令在 Windows PowerShell 中执行。已有项目或虚拟环境时可跳过对应创建步骤。

~~~powershell
git clone https://github.com/nailong0822/AI-lifelab.git
cd AI-lifelab

py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
~~~

### 2. 创建配置

从模板创建 `.env`，保留已有配置：

~~~powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
~~~

编辑项目根目录 `.env`，填写 `ZHIHU_ACCESS_SECRET`。管理员需要服务端默认模型时填写 `DEEPSEEK_API_KEY`，需要联网工具时填写 `TAVILY_API_KEY`。其余配置可先保留模板默认值。

### 3. 构建并启动

推荐比赛演示使用单端口运行：FastAPI 同时提供 API 和构建后的前端。

~~~powershell
npm --prefix frontend ci
npm --prefix frontend run build

.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
~~~

打开 [本地应用](http://127.0.0.1:8000)。登录后进入“模型设置”，配置或核对当前账号的 DeepSeek Key，即可开始探索。

任务执行器当前采用**单进程**运行方式，不要添加多个 Uvicorn worker。首次启动会自动创建数据库和必要数据表。

访问 Vite 输出的本地地址，默认通常是 [http://127.0.0.1:5173](http://127.0.0.1:5173)。`/api` 请求通过 [vite.config.ts](frontend/vite.config.ts) 代理至后端 8000 端口，保留现有 `changeOrigin: false` 设置。

### 6. 首次体验

1. 注册或登录，在“模型设置”核对可用的 DeepSeek Key。
2. 使用首页模板补充自己的【背景】【目标】【已有基础】【可投入时间与约束】，开始检索。
3. 根据奶龙气泡完成必要澄清，查看 Trace、案例匹配分、字段证据与来源。
4. 点击“探索我的人生路径”，比较候选航线或填写自定义方向。
5. 完成当前行动，收集星星；遇到困难时点击奶龙，或从任务进入“记录 / 求助”。需要查找公共资料时可按需联网。
6. 阶段任务处理完成后登舱前往下一站；探索告一段落时进入“经历复盘”，先核对私人草稿，再决定是否匿名分享。

## 环境配置与预算

配置模板见 [.env.example](.env.example)。进程环境变量优先于 `.env`；修改服务配置或预算后重启后端。

### 服务配置

| 变量 | 默认值 / 要求 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 空 | 管理员默认使用的服务端 Key；普通用户不回退使用它 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 模型服务地址 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 统一模型名 |
| `ZHIHU_ACCESS_SECRET` | 需填写 | 知乎搜索鉴权凭证，需有效授权及调用额度 |
| `TAVILY_API_KEY` | 可选 | 搜索与正文提取；留空时可聊天，但不能联网 |
| `LIFELAB_DATA_DIR` | 项目根目录下 `.data` | 可选的数据存储目录 |

知乎适配位于 [backend/providers.py](backend/providers.py)，通过服务端调用知乎搜索接口，使用 Bearer Access Secret 与请求时间戳。凭证不写入前端源码。获取授权请查看 [知乎开放平台](https://developer.zhihu.com/)。

### 工作流预算

| 配置项 | 默认值 | 作用范围 |
| --- | ---: | --- |
| `RETRIEVAL_TOKEN_BUDGET` | 100000 | 单次检索累计 Token |
| `RETRIEVAL_TIME_BUDGET` | 180 秒 | 单次检索活跃时间 |
| `PATH_CANDIDATE_TOKEN_BUDGET` | 80000 | 候选航线生成、阶段任务展开 |
| `PATH_PLAN_TOKEN_BUDGET` | 80000 | 选定方向后的计划生成 |
| `PATH_REVISION_TOKEN_BUDGET` | 80000 | 单次计划调整 |
| `COMPANION_TOKEN_BUDGET` | 80000 | 普通陪伴单轮累计 Token |
| `COMPANION_TIME_BUDGET` | 60 秒 | 普通陪伴单轮活跃时间 |
| `COMPANION_WEB_TOKEN_BUDGET` | 100000 | 实际联网的陪伴单轮预算下限 |
| `COMPANION_WEB_TIME_BUDGET` | 90 秒 | 实际联网的陪伴单轮时间预算下限 |
| `WEB_SEARCH_TIME_BUDGET` | 40 秒 | 联网请求累计活跃时间，仍受整轮时间约束 |
| `EXPERIENCE_TOKEN_BUDGET` | 80000 | 单次经历复盘累计 Token |
| `EXPERIENCE_TIME_BUDGET` | 180 秒 | 单次经历复盘活跃时间 |

候选生成、调整与阶段展开的活跃时间上限为 60 秒，计划生成为 90 秒；人工等待暂停活跃计时。各流程预算相互独立。

联网证据还有独立的上下文控制：

| 配置项 | 默认值 | 用途 |
| --- | ---: | --- |
| `WEB_EVIDENCE_TOKEN_BUDGET` | 10000 | 用于适用性核对的原文节选预算 |
| `WEB_CONTEXT_TOKEN_BUDGET` | 18000 | 最终回答的搜索上下文预算 |
| `WEB_SEARCH_CACHE_SECONDS` | 1800 秒 | 公共资料缓存时间；设为 0 禁用跨轮缓存 |

**Token 预算是一次操作内多次模型调用的累计额度，不是单次回复长度。**单次输出和输入仍受代码中的请求限制、模型上下文与供应商限制约束。预算控制结合请求前估算和模型返回用量；估算值会带标记，达到预算时保留已有结果并说明未完成部分。

检索请求上限与 `10 / 6 / 5 / 5` 的默认返回数量目前定义在 [backend/config.py](backend/config.py)，不是额外的 `.env` 开关。

## 账号权限与数据

### 账号规则

| 类型 | 注册 / 登录方式 | 模型 Key | 管理后台 |
| --- | --- | --- | --- |
| 普通用户 | 用户名 + 至少 8 位密码 | 必须填写自己的 Key | 无 |
| 普通管理员 | 注册时选择管理员，填写邀请码 `lbrnb666` | 个人 Key 优先，否则使用服务端 Key | 有 |

主管理员和普通管理员当前权限相同。以上固定账号和邀请码用于本地演示，当前在 [backend/auth.py](backend/auth.py) 中定义；对外部署前需改造固定凭证与邀请码，并提供现有账号的凭证更新能力。

“模型设置”支持添加、更新、测试与删除 Key，只显示末四位。管理员删除个人 Key 后恢复使用服务端默认 Key；普通用户删除后需要重新配置。后台任务及重启恢复按持久化记录的所属用户解析 Key，避免使用其他账号的配置。

普通用户只能访问自己的任务、路径、对话、记忆与私人案例。管理员页面提供注册用户数、普通用户数、管理员数、当日新增、账号查询，以及用户**最终生成的经历复盘与案例摘要**，不提供逐轮聊天审阅界面。

### 数据存储与备份

| 文件 | 内容 |
| --- | --- |
| `.data/lifelab.db` | 账号、会话、加密 API Key、检索来源、案例、路径版本、进度、对话、记忆、复盘、共享索引与事件 |

## 测试与常见问题

### 运行检查

在项目根目录执行：

~~~powershell
# 后端工作流与接口测试
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 前端奖励 / 传送逻辑测试
node --test frontend/tests/journey-progress.test.mjs frontend/tests/journey-transfer.test.mjs

~~~

后端测试使用虚构数据、模型桩与 mock HTTP，覆盖检索预算、澄清与重启恢复、引用核验、路径版本与推进、陪伴操作确认和撤销、记忆、联网重排与证据、经历分享撤回、账号权限和数据隔离。它们不等于真实供应商连通性测试。

前端测试覆盖完成奖励、跳过与撤销、刷新与轮询防重播、已保存的阶段推进、航线提交成功 / 失败、旧版本状态等。动画外观、三维渲染及响应式布局另需浏览器检查。

### 常见问题

| 问题 | 处理方式 |
| --- | --- |
| Windows 出现 `WinError 10013`，8000 无法监听 | 换用可用端口，例如在 Uvicorn 参数中改为 `--port 8001`；访问地址也改为 8001。开发模式还要同步修改 Vite 的 `/api` 代理目标。 |
| 页面提示前端尚未构建 | 在根目录执行 `npm --prefix frontend run build`，首次构建后再启动后端。 |
| 运行后找不到 `backend` 模块 | 检查工作目录是否为项目根目录，使用项目虚拟环境并以 `-m uvicorn backend.app:app` 启动。 |
| 普通用户仍提示缺少模型 Key | 登录后在“模型设置”保存个人 Key；仅填写服务端 `.env` 不会为普通用户启用模型。 |
| 知乎鉴权或调用受限 | 检查服务端 Access Secret、开放平台授权及额度；查看 Trace 的服务错误与结束原因。 |
| 找到了来源，但案例少或没有完全匹配背景 | 来源需经过经历筛选、字段核验和评分，命中数量不等于有效案例数；也可能受预算影响，查看待分析来源和缺口。 |
| 还显示“需要了解”的缺口 | 不一定是 Token 用完，也可能是案例稀缺、四次请求结束、时间不足或需要用户实际行动验证，以报告结束原因为准。 |
| 联网按钮不可用 | 填写 `TAVILY_API_KEY` 并重启后端；联网未配置不影响普通聊天。 |
| 看不到新界面 | 后端静态模式需要重新构建前端，再刷新；Vite 开发模式使用自己的访问地址。 |
| 星球显示为静态图 | 检查 WebGL2、低内存 / 节流条件、动态场景开关与系统减少动态效果偏好。 |
| 完成任务后没有立即换星球 | 先等待奶龙收集行动之星，再点击“登舱，前往下一站”；只看阶段预览不会推进进度。 |

## 当前边界与后续方向

项目已经具备有界 Agent Loop、部分上下文裁剪、工具封装、结构化校验、预算管理和真实事件观测能力；这些能力目前分布在各工作流中，尚未抽成独立、统一的 Agent Harness。

授权案例回流形成的是**经验积累与检索增强闭环**，不代表模型权重已经自训练，也不代表系统会自动改写提示词或修改自身代码。

后续可继续推进：

- 统一 Context Manager、Agent Loop、Tool Runtime、Budget 与 Observability 接口，减少三个 Agent 的重复实现。
- 建立固定评测集，分别评价检索匹配、引用准确性、路径可执行性与陪伴操作正确性。
- 将反馈用于检索策略与提示词版本实验，经过离线评测、审阅和可回滚发布后再启用。
- 在多用户规模扩大后再评估向量召回、独立任务队列、PostgreSQL 及多进程运行方案。

当前案例数量与来源覆盖受外部资料和调用额度影响；计划投入仅为估计，任务完成来自用户反馈，匹配分不构成结果保证。Web 引用校验可拦截部分无依据内容，但重要事实仍应核对原文。
